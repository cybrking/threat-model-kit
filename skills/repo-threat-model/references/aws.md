# AWS observation profile

Read this when supplied repositories include AWS infrastructure or the user provides AWS read access. Use available authorized CLI/SDK/connectors; this skill does not require a particular connector or provision permissions.

1. Establish the authorized identity, accounts, regions, and environment. Verify actual account identity when allowed. Enumerate relevant service domains rather than treating one successful query as complete cloud visibility.
2. Inspect relevant resource configuration and metadata: network/public exposure, storage policies, identity/trust policies, encryption/key access configuration, service roles, logging, build/deployment metadata, and administrative access. Follow pagination and record failures and service coverage. Do not retrieve secret values, customer records, private object bodies, or other data-plane payloads merely because credentials allow reads.
3. For permission-sensitive scenarios, identify subject, action, resource, context, enforcement point, tenant identity source, and policy layers. Depending on the scenario these can include identity/resource policies, trust policies, permissions boundaries, session policies, organization SCPs/RCPs, KMS policies/grants, network endpoint policies, and service-specific controls. If relevant layers cannot be inspected, effective access remains partial or unknown.
4. Reconcile deployed resources with repository infrastructure and built artifact identities. Record collection times and unknown source-to-runtime mappings. Treat observations as point-in-time; deployment can change during assessment.
5. Record missing access and scope in the model and assessment report. Repository-only findings remain useful but do not confirm deployment-dependent prerequisites. Proposed cloud controls require implementation and appropriate verification before closure.

An applicable explicit deny overrides an allow; missing allows and explicit denies are different. Do not infer effective authority by checking a single policy. See [AWS policy evaluation](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html) and [explicit versus implicit denies](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic_AccessPolicyLanguage_Interplay.html). Confirm current service-specific semantics when they determine a finding; external catalogs are context, not local evidence.

AWS access is optional. `scope.aws_access` uses `available`, `partial`, `denied`, or `not_requested`; available/partial observations need identified account/region scope and a collection time, partial/denied access needs gaps, and not-requested access has no collection time. The helper reports contradictory declarations. The access record does not enforce credential permissions.
